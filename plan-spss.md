# SPSS Analysis Feature — Implementation Plan

> **Scope (confirmed with user):** Full SPSS suite — `.sav` import/export **and** a
> statistical analysis engine (descriptive stats, t-test, ANOVA, chi-square,
> correlation, regression) with a results UI. Data sources: **both** uploaded
> datasets (CSV / Excel / SPSS `.sav`) **and** existing radiology/patient
> records in Postgres.

---

## 0. Goal

Add a self-contained **Analysis** area to the existing Medical Radiology Data
Collection app that lets a researcher:

1. Import a dataset from **CSV, Excel (xlsx), or SPSS `.sav`** (and from a query
   over existing patients/records).
2. Inspect variables, assign measurement levels (scale / ordinal / nominal),
   and define value labels.
3. Run standard analyses with a guided UI and see **tables + charts**.
4. Export results to **PDF/Excel/CSV** and export any dataset back to **SPSS
   `.sav`** (and `.zsav`).

The feature must reuse existing auth, DB, storage, i18n, UI, and API-client
conventions — no new infra (no Redis/Kafka/extra services).

## 2. Library Decisions

### SPSS `.sav` I/O (Node + browser, pure TS)
- **Primary writer/reader:** `@irbisadm/statfmt` — pure TypeScript, no native
  addons, reads & writes SPSS `.sav`/`.zsav`/`.por` (and Stata/SAS). Supports
  variable types, labels, value-label sets, and missing values — exactly what
  SPSS export needs.
- **Complementary reader:** `datareader-spss` — pure TS, read-only but
  validated against R `haven`/`ReadStat` (very accurate metadata + missing
  handling). Use as a cross-check / fallback parser if `@irbisadm/statfmt`
  misreads an edge-case file.

### Statistics engine
- **`jstat`** — distribution CDFs/inverses (normal, student-t, F, chi-square)
  → used to compute **p-values** for t-tests, ANOVA, chi-square, and Pearson
  correlation; also provides descriptive helpers.
- **Regression:** implement OLS ourselves with `@stdlib/matrix` or `ml-matrix`
  + `ml-regression-linear` (small, dependency-light) for linear regression;
  logistic regression via a lightweight Newton-Raphson if needed later.
- Keep all math in a **framework-agnostic workspace package** so it is unit-
  testable and reusable.

No other new runtime deps on the frontend (Recharts/jspdf/exceljs already
present).

## 3. New Workspace Package: `@workspace/stats`

Create `lib/stats` (same shape as `lib/db`, `lib/api-zod`):

```
lib/stats/
  package.json
  tsconfig.json
  src/
    types.ts          # Variable, DataType, MeasureLevel, Dataset, Cell
    dataset.ts        # load from rows, typing inference, missing handling
    spss-io.ts        # readSav/writeSav wrappers (statfmt + datareader-spss)
    excel-io.ts       # xlsx/exceljs import (reuse existing import logic)
    csv-io.ts         # papaparse or xlsx csv
    describe.ts       # descriptive statistics
    tests/
      ttest.ts        # independent & paired, one/two-sided
      anova.ts        # one-way ANOVA (F, p)
      chisquare.ts    # independence + goodness-of-fit
      correlation.ts  # Pearson & Spearman
      regression.ts   # OLS linear (coeffs, R², SE, t, p)
    index.ts
  tests/              # node --test unit tests w/ known datasets
```

The backend imports `@workspace/stats`; the package is pure TS and can later
also run in the browser for instant client-side preview (optional future).

## 4. Data Model (Drizzle — `lib/db/src/schema`)

Add tables (no destructive changes to existing tables):

- **`analysis_datasets`** — `id`, `owner_id` (FK users), `name`, `source`
  (`upload` | `query`), `format` (`csv`|`xlsx`|`sav`|`db`), `row_count`,
  `object_key` (private MinIO key for the raw uploaded file, nullable for
  `db`-sourced), `created_at`, `updated_at`.
- **`analysis_variables`** — `id`, `dataset_id` (FK), `name`, `label`,
  `data_type` (`numeric`|`string`|`date`), `measure` (`scale`|`ordinal`|
  `nominal`), `missing_values` (jsonb), `value_labels` (jsonb).
- **`analysis_runs`** — `id`, `dataset_id`, `type` (`descriptive`|`ttest`|
  `anova`|`chisquare`|`correlation`|`regression`), `config` (jsonb: selected
  variables, groups, test options), `result` (jsonb: tables + stats),
  `created_at`, `owner_id`.

Seed `analysis_variables` automatically on dataset import from column headers
+ inferred types (numeric detection, measure default = scale; strings =
nominal). User can edit measure/value-labels in the UI.

Migration: add `scripts/db-migrate` step (drizzle `push`/migration) — non-
destructive, additive only.

Endpoints (also added to `openapi.yaml`):

| Method | Path | Purpose |

| GET  | `/api/analysis/runs/:id` | fetch a saved run result |
| POST | `/api/analysis/datasets/:id/export` | export dataset to `.sav`/`.zsav` (statfmt) → stream/download |

  under the **private** bucket (`radiology-objects/analysis/...`); never expose

- Reuse session auth + `express.json({limit:"50mb"})` (already set) for config

- Validation with **zod** schemas (mirror into `lib/api-zod` so frontend gets
  shared types).
- Errors: typed error responses; never leak S3 creds or raw stack traces.

## 6. Statistical Engine Detail (formulas, all p-values via `jstat`)

- **Descriptive:** n, mean, median, std (sample+pops), variance, min, max,
  quartiles, skewness, kurtosis, missing count, frequency table for categorical.
- **Independent t-test:** Welch's (default) + Student's; df via Welch–Satterthwaite; p = `2*jStat.studentt.cdf(-|t|, df)` (two-sided). Paired t-test from diffs.
- **One-way ANOVA:** between-group SS / within-group SS → F; p = `1 - jStat.centralF.cdf(F, k-1, N-k)`.
- **Chi-square:** build contingency table; χ² = Σ (O−E)²/E; p = `1 - jStat.chisquare.cdf(χ², df)`; report Cramér's V.
- **Correlation:** Pearson r + t = `r·√((n−2)/(1−r²))`, p via student-t; Spearman via ranked data.
- **Linear regression (OLS):** `β = (XᵀX)⁻¹Xᵀy`; R², adjusted R², SE(β), t, p per coefficient, residuals. Use `ml-matrix` for inversion.
- All functions return a **structured result** (tables as row/col arrays +
  metadata) so the UI renders uniformly and export is trivial.

## 8. UI/UX Flow

1. User opens **Analysis** in nav → sees datasets + "Upload" / "From existing
   data".
2. Upload → progress → lands on dataset page with auto-detected variables.
3. User fixes measurement levels (important: t-test/ANOVA need scale; chi-square
   needs nominal).
4. Pick a test → select variables → **Run** → results appear with chart + table
   + interpretation hints (e.g., "p < 0.05 → significant").
5. Export result (PDF report / Excel) or export cleaned dataset to `.sav` for
   sharing with SPSS colleagues.

Keep it guided and forgiving: disable invalid variable choices per test, show
inline validation messages, surface missing-value handling clearly.

## 9. Security & Conventions

- Reuse `requireAuth`; datasets/runs scoped to `owner_id`.
- Uploaded raw files + generated `.sav` go to the **private** MinIO bucket;
  served only through authenticated backend endpoints (presigned/stream), never
  public.
- Validate file type by magic bytes (not extension) for `.sav`; size-limited.
- No new secrets; reuse `SESSION_SECRET`, S3 env already present.
- No new infrastructure (per project rule): engine is a package, storage is
  existing MinIO/Postgres.

- `@workspace/stats`: unit tests against **known datasets with published

- Backend: upload csv/xlsx/sav → dataset created; bad file rejected; run each

- Frontend: component smoke tests for builder/results; manual E2E of full flow.
- Run existing `pnpm run typecheck` + `pnpm -r test` to ensure no regressions.

## 12. Success Criteria

- Upload CSV/Excel/SPSS `.sav` → variables auto-detected; existing radiology
  data can be turned into a dataset.
- Each analysis (descriptive, t-test, ANOVA, chi-square, correlation,
  regression) returns correct statistics + p-values (validated vs references).
- Results render as tables + charts; exportable to PDF/Excel/CSV.
- Any dataset exports to a valid `.sav`/`.zsav` re-openable in SPSS.
- Auth enforced; files stored privately in MinIO; no new infra; typecheck/build
